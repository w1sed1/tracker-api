Ідея
Почати звичку легко, а втримати — важко.

Трекер рахує серії та відсотки, але цифри не відповідають на головне: чому звичка зривається і що змінити.

Додамо до трекера AI-коуча.
  • Трекер — зберігає відмітки й рахує статистику;
  • Gemini — читає статистику й пише висновки та поради.

Цифри перетворюються на конкретний план на тиждень.

Обрано Google Gemini API.
  • структурована відповідь: модель повертає JSON за нашою схемою — програмі не треба розбирати текст;
  • простий REST: один POST-запит, достатньо стандартної бібліотеки Python;
  • безкоштовний рівень — без підключення білінгу.
Gemini API
Gemini — сімейство моделей Google, що розуміють текст, зображення, аудіо, відео та PDF; контекст — до 1 млн токенів.

У проєкті — дві моделі через Interactions API:

  • Gemini 3.8 Flash — основна: аналізує статистику й підбирає звички;
  • Gemini 3.5 Flash-Lite — запасна, якщо основна перевантажена.

Gemini Developer API

доступ за API-ключем, безкоштовний рівень — для прототипів (використано в проєкті).

Vertex AI (Google Cloud)

доступ через IAM, SLA, вибір регіону зберігання даних — для промислового використання.

Як це працює: що в хмарі, а що локально

У хмарі

аналіз статистики, висновки й поради, підбір звичок під ціль — уся робота моделі на GPU Google.

Локально

зберігання відміток, підрахунок серій і відсотків, графіки та інтерфейс.

Запит до Gemini API
POST https://generativelanguage.googleapis.com/v1beta/interactions
x-goog-api-key: <ключ>            Api-Revision: 2026-05-20

{
  "model": "gemini-3.8-flash",
  "system_instruction": "Ти — уважний коуч зі звичок…",
  "input": "Проаналізуй мою статистику… {\"habits\": [ … ]}",
  "response_format": {
    "type": "text", "mime_type": "application/json",
    "schema": { "type": "object", "properties": {
      "summary": …, "strengths": …, "habits": …, "focus": … } }
  },
  "store": false                   // не зберігати діалог на сервері
}
  • Відповідь: крок model_output з текстом — JSON, що відповідає схемі; usage — кількість токенів.
  • Коди 429 / 503 (ліміт, перевантаження) → той самий запит до запасної моделі.
Веб-інтерфейс
  1. Відмічати звички щодня одним кліком.
  2. Дивитися статистику: серії, відсотки, графіки.
  3. Натиснути «Проаналізувати» — отримати висновки й поради.
Під відповіддю — час запиту, модель і кількість токенів.
Що вміє програма
  • Відмічати звички за останні 7 днів одним кліком.
  • Статистика: поточна й рекордна серії, відсоток виконання, графіки по тижнях і днях тижня, календар за пів року.
  • AI-звіт: загальна оцінка, сильні сторони, статус і порада для кожної звички, фокус на тиждень.
  • Підбір звичок під ціль: «краще висипатися» → 3 звички, кожну можна додати одним кліком.
  • Відповідь моделі — JSON за схемою, тож інтерфейс одразу показує її картками.
  • REST API зі Swagger-документацією — для вбудовування в інші системи.
  • Якщо хмарна модель перевантажена — автоматично переходить на запасну.
Чого програма не вміє
  • Бачить лише цифри: не знає причин пропусків, настрою чи обставин.
  • Поради — загальні рекомендації, а не медична чи психологічна консультація.
  • Може неточно витлумачити статистику — звіт варто перевіряти.
  • Звіт формується за запитом: ні щотижневих звітів, ні нагадувань.
  • Без інтернету AI-функції не працюють (трекер і статистика — працюють).
  • Це прототип: запускається локально, один користувач, без акаунтів.
Більшість обмежень — свідомі спрощення прототипу, а не обмеження хмарного сервісу.

Сфери застосування
  • Здоров’я й фітнес: аналіз тренувань, сну, харчування;
  • Освіта: розбір успішності й персональний план навчання;
  • Фінанси: категорії витрат і поради щодо бюджету;
  • HR: підсумки опитувань і звітів команди;
  • Підтримка клієнтів: класифікація звернень у JSON;
  • Бізнес-аналітика: текстові висновки до дашбордів;
  • Документи: витяг полів з договорів і рахунків;
  • IoT: пояснення показників датчиків.
Ключова можливість — structured output: відповідь моделі одразу стає даними для програми. Так AI-аналіз можна вбудувати у власний продукт через публічний API.
Як розвинути проєкт у хмарі
  • Cloud Run (PaaS) — розгорнути сервер у хмарі: доступ з телефона й автоматичне масштабування.
  • Firestore або Cloud SQL — хмарна база замість локального файлу SQLite.
  • Firebase Authentication — акаунти: кожен бачить лише свої звички.
  • Cloud Scheduler — щонеділі формувати AI-звіт автоматично.
  • Firebase Cloud Messaging — нагадування про звички на телефон.
  • Vertex AI — для чутливих даних про здоров’я: вибір регіону й гарантії щодо даних.
Кожен крок — ще один керований хмарний сервіс, а не власна інфраструктура.
Висновки
  1. Хмарний AI-сервіс перетворює сирі цифри статистики на зрозумілі висновки й поради — без власних моделей і GPU.
  2. Structured output повертає JSON за схемою: інтеграція — один HTTP-запит без розбору тексту.
  3. Модель оплати pay-as-you-go: прототип — безкоштовно, у платному рівні — [[EX_COST_SHORT]] за звіт.
